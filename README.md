# Elio

Elio is a compiler for GPU compute shaders. You write a compute kernel once in a
small language (`.elio`), and Elio emits the equivalent shader for several
graphics APIs — WGSL (WebGPU), GLSL (Vulkan / GLES 3.1), and Metal (MSL) — plus
a CPU implementation for platforms that have no compute support at all. It is
built for the GoSX renderer, but the core compiler has no GoSX dependency.

## What problem it solves

A GPU compute kernel — culling, particle integration, a prefix sum, skinning —
has to be written separately for each graphics API: WGSL for WebGPU, GLSL for
Vulkan and GLES 3.1, MSL for Metal. WebGL and GLES 2.0 have no compute stage at
all, so the same work has to be re-implemented on the CPU there. In GoSX this
showed up concretely: the particle integrator existed in four hand-written
copies (WebGPU/Go, WebGL/JS, Android/Kotlin, iOS/Swift), and there was no
portable path for culling, post-processing, or simulation.

Elio replaces those copies with one source. The same kernel is checked to be
valid on each backend: WGSL is validated with `naga`, GLSL is compiled to SPIR-V
with `glslangValidator`, and the CPU implementation is run and its results
compared — see `conformance/`.

It is one of three related M31 Labs compilers: Selena compiles material/shader
source for the rasterization pipeline, Eos compiles ML inference, and Elio
compiles per-frame compute. They are separate tools that share the same parser
tooling and target the same GPU device.

## Pipeline

```
.elio source ──parse──▶ IR ──┬──▶ WGSL   (WebGPU; validated by naga)
                             ├──▶ GLSL    (Vulkan / GLES 3.1; glslang → SPIR-V)
                             ├──▶ Metal    (MSL)
                             └──▶ CPU      (scalar interpreter; WebGL / GLES 2.0)
```

## CLI

```sh
go install m31labs.dev/elio/cmd/elio@latest

elio emit wgsl  kernel.elio    # WGSL to stdout
elio emit glsl  kernel.elio    # GLSL #version 450 compute
elio emit metal kernel.elio    # Metal MSL
elio check      kernel.elio    # parse-check only
elio emit ts --set ocean       # TypeScript module of the ocean kernels
```

## The `.elio` language

Types are spelled in a Go-flavored way to avoid the `<…>` ambiguity of WGSL
generics: `[N]T` and `[]T` for fixed and runtime arrays, `atomic_u32`,
`vec2/3/4` (suffix `u` for unsigned), `mat3` / `mat4`. Bindings, a workgroup
size, and a kernel entry point are declared at the top level; the body is
ordinary imperative code (`let` / `var`, `if`, `for`, indexing, atomics).

```elio
@group(0) @binding(0) uniform cull: CullUniforms;
@group(0) @binding(1) storage read input: []InstanceRecord;
@group(0) @binding(2) storage read_write output: []InstanceRecord;
@group(0) @binding(3) storage read_write drawArgs: [4]atomic_u32;

@workgroup(64) kernel main(gid: global_invocation_id) {
  let i = gid.x;
  if i >= arrayLength(&input) { return; }
  let record = input[i];
  let center = record.model[3].xyz;
  var inside = true;
  for (var p: i32 = 0; p < 6; p = p + 1) {
    let plane = cull.planes[p];
    if dot(plane.xyz, center) + plane.w < -cull.radius { inside = false; break; }
  }
  if inside {
    let slot = atomicAdd(&drawArgs[1], 1u);
    output[slot] = record;
  }
}
```

## How it integrates with GoSX

Elio targets GoSX's `render/gpu` package rather than a GPU API directly, and
attaches to the renderer through `render/compute.ExternalComputePass`. A pass
records its dispatch onto the frame's command encoder and publishes the buffers
it produced onto a small resource descriptor (`render/compute.GPUResource`); the
renderer's draw step then reads those buffers. The `InstanceRecord` layout
(80 bytes: a `mat4` plus a `vec4<u32>`) matches the engine's existing instanced
draw, so a kernel that writes instance records can drive a draw without changes
to the renderer. `examples/cull` is a working out-of-tree pass whose shader is
generated by this compiler.

## Gather kernels and WebGL2

WebGL2 has no compute shaders. A kernel that fits the *gather profile* can run
there instead, as one fullscreen render pass over float textures. `emit/gather`
lowers it to a GLSL ES 3.00 fragment shader; `sema.CheckGather` explains why a
kernel does not qualify.

**What the profile allows.** Each invocation writes only its own element.

1. No `shared` memory, barriers or atomics.
2. The only builtin is `global_invocation_id`.
3. Every buffer write has the form `buf[i] = value`, where `i` is `gid.x` or a
   `let` bound directly to `gid.x`. No field or swizzle writes into an element.
4. At most four buffers are written. A written buffer is `read_write` and the
   kernel never reads it.
5. Buffer elements are `f32`, `vec2<f32>` or `vec4<f32>`. No structs.
6. Uniform blocks hold scalars (`f32`, `i32`, `u32`) and vectors of them.

**Host contract.** `gather.Emit(module, kernel)` returns the shader source and
a `Layout`.

- Every buffer is a 2D float texture, `elio_width` texels wide. Element `i` is
  texel `(i % elio_width, i / elio_width)`. Set `uniform uint elio_width`
  before the pass.
- Each entry in `Layout.Inputs` is a `sampler2D` uniform (`Sampler`, for example
  `src_tex`) and a `uint` uniform with the element count (`Length`, for example
  `src_len`). Bind the texture with `NEAREST` filtering.
- Each entry in `Layout.Outputs` is a color attachment at `Location`. Unused
  channels are zero.
- Each entry in `Layout.Uniforms` is a `std140` block. Find it with
  `getUniformBlockIndex(program, Block)`.
- One dispatch is one fullscreen pass. Draw a triangle or quad over a viewport
  of `elio_width` by `ceil(count / elio_width)` pixels. Pixels past `count` run
  the kernel with an out-of-range `gid.x`, so keep the usual bounds check.
- Render targets are `RGBA32F` or `RGBA16F`. WebGL2 needs the
  `EXT_color_buffer_float` extension (or `EXT_color_buffer_half_float` for
  `RGBA16F`) to render to them. `RGBA16F` stores the values rounded to half
  precision.

**Example.** `ir.ScaleBias()` (`dst[i] = src[i] * params.scale + params.bias`)
emits:

```glsl
#version 300 es
precision highp float;
precision highp int;
precision highp sampler2D;

uniform uint elio_width;

layout(std140) uniform Params_ubo {
  vec4 scale;
  vec4 bias;
} params;
uniform highp sampler2D src_tex;
uniform uint src_len;
layout(location = 0) out vec4 dst_out;

vec4 src_at(uint i) {
  return texelFetch(src_tex, ivec2(int(i % elio_width), int(i / elio_width)), 0);
}

void main() {
  dst_out = vec4(0.0);
  uint i = (uint(gl_FragCoord.y) * elio_width + uint(gl_FragCoord.x));
  if ((i >= src_len)) {
    return;
  }
  dst_out = ((src_at(i) * params.scale) + params.bias);
}
```

The emitted source is checked with `glslangValidator` in `conformance/`. It has
not been run on a WebGL2 device.

## Textures, FFT, ocean kernels and `emit ts`

**Storage textures.** A write-only 2D texture binds as
`@group(0) @binding(3) storage write dst: tex2d_rgba16float;` (also
`tex2d_rgba32float` and `tex2d_r32float`). A kernel writes it with
`textureStore(dst, vec2u(x, y), vec4(...))` and reads its size with
`textureDimensions`. The interpreter holds one in a `run.Texture` and rounds
each store to the format's precision. A gather kernel treats a texture it
writes at `vec2u(i % W, i / W)` as a color attachment (see below).

**Sampled textures.** A read-only 2D texture (`texture_2d<f32>`, no sampler)
binds as `@group(0) @binding(1) texture src: tex2d;`. A kernel reads it with
`textureLoad(src, vec2u(x, y), level)` (a `vec4`; `level` is a `u32`, 0 for the
base level) and sizes a level with `textureDimensions(src, level)`. Emitted as
`texture_2d<f32>` and `textureLoad` (WGSL), `sampler2D` and `texelFetch`
(GLSL 450), `texture2d<float, access::read>` and `.read` (Metal). In the
interpreter, bind a `*run.Texture`; its optional `Levels` field holds the
chain below the base (level `L > 0` is `Levels[L-1]`), and a load outside a
level returns zeros, as WebGPU does. In a gather kernel a sampled texture is an
input: a `uniform highp sampler2D <name>` read with `texelFetch`, with no
`elio_width` linearization, and `Layout.Inputs` marks it `Kind: "texture"`
(buffers are `Kind: "buffer"`).

**FFT.** `stdlib.FFT2DCompute(n)` builds a 2D complex FFT as two compute
kernels, `fft_rows` and `fft_cols`, that use workgroup memory (`n` from 4 to
256, a power of two). `stdlib.FFT2DGather(n)` builds one Stockham stage,
`fft_stage`, in the gather profile: the host runs log2(n) passes per axis and
swaps the source and destination textures between passes.

**Gather outputs.** `gather.Emit` returns the GLSL ES source and a `Layout`
that names each input sampler, each output color attachment (with its texture
format) and each std140 uniform block. At most 32 bytes per pixel are written
across all outputs.

**Ocean kernels.** `stdlib` holds six kernels for an FFT ocean: `ocean_spectrum`
(JONSWAP spectrum for one cascade), `ocean_evolve` (advance the spectrum to a
time), `ocean_assemble` (choppiness, displacement and slope textures),
`ocean_mip` (box-filtered mip levels, read from a sampled texture), `ocean_foam` (persistent crest foam) and
`ocean_probe` (height and normal at up to 64 world points). Each source file
under `stdlib/ocean/` documents its model, units and buffer layout.

**Ship wake.** Three more gather kernels, `wake_source`, `wake_symbol` and
`wake_step`, simulate a ship's wake in a 256 x 256 toroidal window of the water
frame. The surface obeys d²h/dt² = -g Q[h + p/(ρg)] with Q = |k| applied exactly
by the existing inverse FFT (so deep-water dispersion holds up to the grid's
Nyquist limit, and a moving pressure patch sheds a Kelvin wedge of half-angle
19.47°). `ocean_foam` can follow the wake's turbulence for the white trail. The
ocean graphs run the wake when the bool param `wakeEnabled` is set; the hull's
pose is the params `hullX`, `hullZ`, `hullHeading` and `hullSpeed`, either set by
the app or read from a scene node (`graph.SourceNode`). The surface binds the
`wake` export (height, slope and turbulence). Each source file under
`stdlib/ocean/` documents its units.

**Float32 mode.** `run.RunWith(..., run.Options{Float32: true})` rounds every
float result to float32, so the interpreter matches a GPU's `f32` arithmetic up
to the accuracy of its math functions. The default stays float64.

**`elio emit ts`.** `elio emit ts --set ocean` writes one TypeScript module to
stdout. For each kernel it exports `<name>WGSL`, `<name>Entry`,
`<name>Workgroup`, `<name>Bindings` and `<name>Uniforms` (field names, types,
byte offsets and struct size under WGSL layout rules). A gather kernel also
exports `<name>GLSL` and `<name>GatherLayout`, plus `<name>UniformsStd140` when
the std140 layout differs from the WGSL one. The header records the Elio
version and a SHA-256 of the sources, so a checked-in copy shows when it is
stale. The library entry point is `emit/ts.Emit`; `stdlib.OceanKernelSet`
lists the kernels. The emitted WGSL passes `naga` and the GLSL passes
`glslangValidator`; neither has been run in a browser.

## Layout

| Path | Role |
|---|---|
| `ir/` | the compute IR and sample kernels |
| `parse/` | `.elio` front-end (lexer + recursive-descent parser) |
| `emit/wgsl/`, `emit/glsl/`, `emit/metal/` | backend emitters |
| `emit/gather/` | GLSL ES 3.00 fragment emitter for gather kernels (WebGL2) |
| `emit/ts/` | TypeScript module emitter for kernel sets |
| `run/` | scalar CPU interpreter |
| `conformance/` | cross-backend validation (naga + glslang + CPU) |
| `cmd/elio/` | the `elio` CLI |
| `examples/cull/` | an out-of-tree GoSX `ExternalComputePass` |

## Status and roadmap

The compiler is working end to end: parsing, four backends, the CLI, and the
GoSX integration point are in place and tested. Planned work:

- Continue hardening the `grammargen` / `gotreesitter` parser shared with Selena
  and Eos; the former hand-written parser has been retired.
- A direct SPIR-V emitter is optional; SPIR-V is reachable today through the
  GLSL backend and `glslang`.
- Run Elio kernels in the GoSX frame on a WebGPU device shared with Eos. The
  device-sharing interfaces exist on both sides; the dispatch path is the next
  step.

The name is a counterpart to Selena (the rasterization-side compiler).
